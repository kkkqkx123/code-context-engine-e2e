# cce_e2e_tests

`cce_e2e_tests` is the integration test support package for the Code Context Engine. Shared testing capabilities are placed in library crates, while test entry points are layered under `tests/` based on their purpose.

## Directory Responsibilities

- `src/`
  - Shared testing utilities, including fixtures, output writers, assertions, and lightweight test wrappers.
- `examples/`
  - Demonstrative output generators. Running examples generates files under `outputs/` for manual review.
  - **Does not participate in assertions**; separated from `tests/` to avoid decoupling tests from outputs.
  - Subdirectories divided by language: `rust/`, `java/`, `multi_language/` (cross-language scenarios).
  - Examples in subdirectories must be declared as `[[example]]` entries in `Cargo.toml`.
- `tests/`
  - Integration test entry points and scenario modules.
  - `regression.rs` is the entry point for regression tests (performs assertions only, does not write output files).
  - `workflow.rs` is the entry point for workflow tests; scenarios and supporting modules are located in `tests/e2e/`.
  - `benchmark/` contains only descriptions for comparing indexing effects; no performance test implementations are included here.
  - `fixtures/` contains input data dedicated to integration tests.
- `crate root fixtures/`
  - Fixtures used by the `src/` side and `examples/` (maintained in parallel with `tests/fixtures/`).
- `outputs/`
  - Generated by `examples/` for manual review.

## Module Location Standards

- Regression tests are placed in `tests/regression/` and should not be scattered in the root directory.
- Workflow scenarios are placed in `tests/e2e/`; this is an internal support tree. Do not place regression tests here.
- `tests/benchmark/` contains only comparison descriptions, not performance test code.
- `tests/fixtures/` and the root directory `fixtures/` maintain references to the same set of fixtures.

## Entry Point Conventions

- `tests/workflow.rs` is responsible for loading the entire workflow module tree.
- `tests/regression.rs` is responsible for loading the regression test module tree.
- Regression tests perform assertion verification only and do not write output files.
- Output files are generated by examples under `examples/` for manually reviewing changes in output.

## Usage

```bash
# Regression assertions (no output writing)
cargo test -p cce-e2e-tests --test regression -- --nocapture

# Workflow tests
cargo test -p cce-e2e-tests --test workflow -- --nocapture

# Generate demonstrative outputs (run examples)
cargo run --example rust_basic
cargo run --example rust_export
cargo run --example rust_relation
cargo run --example java_spring_boot_export
cargo run --example multi_language_basic
```

## Notes

- Source code files and comments use English.
- Project-related documentation uses Simplified Chinese.
- Output files are not involved in automatic assertions but are used to observe output changes after executing examples.
